本地插件 · 原文不出本机

一条脚本，把星图装到自己电脑上

安装后，思维星图只读本机会话日志，逐轮分析并生成本地星图。它不会接管你的对话， 也不会把原文上传到作者服务器。

一键脚本 · 当前阶段 ./setup.sh

脚本完成依赖安装、前端构建，并生成 600 权限的配置模板（~/.thought-atlas/config.json）； 填上你自己的 Key 后启动守护进程即可。已有配置不会被覆盖。 npm 发布版（npx thought-atlas setup）赛后再提供；当前阶段以源码方式运行。 源码公开在 GitHub：lwl-ManchesterCity/thought-atlas，克隆后跑 ./setup.sh。 如果你在评审当前仓库，请直接打开 回放样例 与 实时沙箱，它们使用同一份分析引擎。

安装后会发生什么

  1. 写入本地配置。 配置位于 ~/.thought-atlas/config.json，文件权限 600。BYOK Key 只存在这里，不进入 git、日志或前端。
  2. 只读接入（可选步骤）。 Codex 与 Qoder 的会话文件由独立 watcher 进程只读轮询上报，setup.sh 不自动启动；需要时运行 node packages/adapters/watcher/src/main.ts。不修改 agent 的任何文件。
  3. 逐轮增量分析。 每轮只把当轮文本与导图骨架（label / summary 级）发给模型，不发送历史原文。
  4. 本机看星图。 浏览器打开 http://127.0.0.1:7788，节点随对话增长；断网不影响聊天，恢复后补跑。 顶部会话选择器可切换各条 Codex / Qoder 会话；已分析过的历史会话不起 watcher 也能直接回看。

适配层是注册制的：Codex 与 Qoder 解析器已内置，共用同一个 watcher 核心（字节游标、重放、去重都在核心里）。 其他 agent 只要实现一个解析器模块（ParserModule），watcher 与守护进程都不用改。

脚本里做了什么（等价手动命令）

npm ci npm run build:web node packages/daemon/src/main.ts

需要 Node.js 22.18+（推荐 24）与本机模型 Key。守护进程默认监听 127.0.0.1:7788，只绑定回环地址，不对局域网开放。

可选：手动标记与删除

自动分析不是终局。你可以手动把某个节点标为转变、删除误记节点；这些操作以隔离的事件序号写入日志， 同样可以回放与审计，不会污染真实对话轮次。

边界提醒：本地插件读取的原文只在本机。公开站点的回放样例当前全部为合成数据； 真实样例必须经作者逐段批准并通过敏感扫描后才会替换。详见 边界与隐私。

常见问题

需要登录或上传对话吗？

不需要。本地插件不提供账号体系，也不上传会话原文；在线沙箱是独立的限量体验，且不持久化原文。

模型 Key 存在哪里？

本地使用 ~/.thought-atlas/config.json（权限 600）。托管演示使用 Sites 应用 Secret，只声明名称 DEEPSEEK_API_KEY，值由作者在站点设置界面亲手录入，前端代码不包含 Key。

分析失败了怎么办？

失败不会丢轮次：聊天不受影响，UI 会标记本轮分析失败；错过的轮次可以补跑。越界的模型输出会整包丢弃，不会写入星图。
